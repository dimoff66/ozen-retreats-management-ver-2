# Архитектура проекта

## Слои приложения

Работа с данными разделена на слои:

```text
React component
    ↓
Entity service
    ↓
Database adapter
    ↓
Supabase
```

Компоненты отвечают за интерфейс и вызывают сервисы сущностей. Компоненты не
должны выполнять прямые запросы к Supabase.

Сервисы содержат прикладную и бизнес-логику: подготовку данных для отображения,
сортировку, вычисление доступности, правила переходов статусов и операции над
сущностями. Сервисы работают с базой только через объект `db`.

`src/services/database.ts` — единственный низкоуровневый адаптер базы данных.
Прямые запросы к Supabase должны находиться только в этом файле. Адаптер
экспортирует объект `db`, содержащий API для сущностей:

```ts
db.users
db.roles
db.houses
db.rooms
db.houseMaps
db.retreats
db.retreatRooms
db.guests
db.guestStatuses
db.taxiRides
db.taxiGuests
```

В зависимости от сущности используются методы вроде `getAll()`, `getById()`,
`getByRetreatId()`, `create()`, `update()` и `delete()`.

## Структура исходного кода

Фактическая структура на данный момент:

```text
src/
├── app/                 # маршруты Next.js и глобальные стили
├── components/          # React-компоненты, сгруппированные по областям
│   ├── common/
│   ├── guests/
│   ├── history/
│   ├── houseMaps/
│   ├── houses/
│   ├── layout/
│   ├── retreats/
│   ├── rooms/
│   └── taxis/
├── contexts/            # React Context, включая текущего пользователя
└── services/            # бизнес-логика, Supabase-клиент и адаптер БД
```

В `src/services/` находятся адаптер `database.ts`, Supabase-клиент
`supabase.ts` и сервисы сущностей, например `guestsService.ts`,
`guestStatusesService.ts`, `houseMapsService.ts` и `taxiRidesService.ts`.

При добавлении функциональности располагайте код рядом с соответствующей
областью проекта и следуйте уже существующим соглашениям. Не создавайте новую
архитектурную структуру параллельно существующей без отдельной необходимости.

## Текущий пользователь

Текущий пользователь приложения доступен через React Context:

```ts
const { currentUser } = useCurrentUser();
```

Если удобно, значение можно переименовать:

```ts
const { currentUser: user } = useCurrentUser();

if (!user) {
  return null;
}
```

Доступные поля пользователя:

```text
id
name
login
role
retreat_id
```

При смене пользователя интерфейс, использующий контекст, обновляется.

## Загрузка данных и границы ответственности

- Компоненты вызывают сервисы и не знают детали запросов к базе.
- Сервисы используют только Database Adapter для операций с базой.
- Бизнес-правила не должны дублироваться в нескольких компонентах.
- Данные для отображения следует подготовить до JSX `return`.
- Не загружайте данные в корневой компонент только ради передачи через длинную
  цепочку props, если их может загрузить соответствующая рабочая область.

## Окружение Supabase

Локальные переменные хранятся в `.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<publishable-or-anon-key>
```

После изменения `.env.local` перезапустите `npm run dev`. Не размещайте
`service_role` или другой секретный ключ в переменной с префиксом
`NEXT_PUBLIC_`.
